## Root Causes Found & Fixed

### Bug 1 — OTP `null` never cleared in MongoDB ⚠️ **Critical**
**What happened:** `order.deliveryOtp = null; await order.save()` does **not** reliably `$unset` a Mongoose `String` field. MongoDB still kept the old OTP value. This meant the send route saved a fresh OTP, but the old stale OTP remained queryable from DB — or vice versa depending on which document instance was cached.

**Fix:** Both routes now use `findByIdAndUpdate` with `$set`/`$unset` — bypasses Mongoose document caching entirely and writes directly to MongoDB.

| Route | Before | After |
|-------|--------|-------|
| `send/route.ts` | `order.deliveryOtp = otp; order.save()` | `Order.findByIdAndUpdate($set: {deliveryOtp})` |
| `verify/route.ts` | `order.deliveryOtp = null; order.save()` | `Order.findByIdAndUpdate($set + $unset: {deliveryOtp})` |

### Bug 2 — No guard against re-verifying delivered orders
Added a guard at the top of verify:
```ts
if (order.deliveryOtpVerification === true || order.status === "delivered") {
    return { message: "This order has already been delivered and verified." }
}
```

### Bug 3 — `!otp` check fails for `otp = "0"` edge case
Changed `if (!otp)` → `if (otp == null || otp === "")` so numeric-string `"0"` isn't rejected.
